# Rin博客系统组件层级开发规范

## 概述

本文档定义了Rin博客系统中所有组件的层级管理规范，确保开发团队在添加新组件或修改现有组件时遵循统一的层级管理原则。

## 核心原则

### 1. 统一管理原则
- **所有z-index值必须通过统一的配置文件管理**
- **禁止在组件中硬编码z-index值**
- **优先使用CSS类而非内联样式**

### 2. 响应式优先原则
- **移动端和桌面端使用不同的层级策略**
- **移动端使用较低的z-index值以优化性能**
- **自动根据屏幕尺寸选择合适的层级**

### 3. 性能优化原则
- **避免使用过高的z-index值**
- **移动端层级范围：1000-1700**
- **桌面端层级范围：10000-11000**

## 开发规范

### 1. 新组件开发

```typescript
// ✅ 正确：使用CSS类
function MyComponent() {
  return (
    <div className="z-modal glass-layer-3">
      {/* 组件内容 */}
    </div>
  );
}

// ✅ 正确：使用响应式Hook
import { useResponsiveZIndex } from '../utils/modal-config';

function MyComponent() {
  const zIndex = useResponsiveZIndex('MODAL');
  
  return (
    <div style={{ zIndex }}>
      {/* 组件内容 */}
    </div>
  );
}

// ❌ 错误：硬编码z-index
function MyComponent() {
  return (
    <div style={{ zIndex: 10300 }}>
      {/* 组件内容 */}
    </div>
  );
}
```

### 2. 现有组件修改

修改现有组件时，必须遵循以下步骤：

1. **检查当前z-index使用情况**
2. **确定合适的层级类型**
3. **替换为统一的CSS类或Hook**
4. **测试响应式表现**

### 3. CSS类命名规范

- 层级CSS类统一使用 `z-` 前缀
- 命名与 `MODAL_Z_INDEX` 中的键名保持一致
- 例：`MODAL_Z_INDEX.HEADER` → `.z-header`

## 测试规范

### 1. 层级冲突测试

- 同时打开多个弹窗，验证层级顺序
- 测试下拉菜单与其他组件的层级关系
- 验证移动端菜单的层级表现

### 2. 响应式测试

- 在不同屏幕尺寸下测试层级切换
- 验证移动端性能优化是否生效
- 测试屏幕尺寸变化时的层级更新

### 3. 性能测试

- 监控移动端的渲染性能
- 验证z-index值是否在合理范围内
- 测试复杂页面的层级渲染效率

## 维护指南

### 1. 定期审查

- 每月审查一次组件层级使用情况
- 检查是否有新的硬编码z-index值

### 2. 文档更新

- 新增组件类型时更新层级分配表
- 修改层级配置时同步更新文档

### 3. 团队培训

- 新成员必须学习层级管理规范

## 常见问题解答

### Q: 为什么移动端要使用较低的z-index值？
A: 较低的z-index值可以减少浏览器的渲染负担，特别是在低端移动设备上，能够显著提升性能。

### Q: 什么时候应该使用内联样式而不是CSS类？
A: 只有在需要动态计算z-index值时才使用内联样式，并且必须通过 `useResponsiveZIndex` Hook获取值。

### Q: 如何处理第三方组件的层级问题？
A: 通过CSS覆盖或包装组件的方式，将第三方组件的层级纳入统一管理体系。

### Q: 层级冲突时如何调试？
A: 使用浏览器开发者工具检查z-index值，确认是否遵循了统一的层级体系，必要时调整组件的层级类型。
